# Fair Shift

Fair Shift checks an hourly worker's pay. Paste a schedule (a LINE message from your manager, your own notes, a timesheet) and the payslip. An agent built on NVIDIA Nemotron (Nebius Token Factory) retrieves the current official minimum wage and the overtime, rest day, holiday, tip credit and spread-of-hours rules for where you work from government websites with Tavily. Code computes what you may be owed line by line, and every rule is shown with its exact quote, article number, link and effective date.

When the input is unclear, the page says so instead of guessing: a shift with no break written, a payslip that only shows take-home pay, a line it could not read, payslip hours that do not match the schedule. It ends with what to do next and a printable report. Taiwan and New York State; English and Traditional Chinese. Built for the Nebius x NVIDIA Global AI Hackathon (Best Apps and Agents; also Best Use of Tavily). Not legal advice. Every sample in this repo is synthetic.

Try it: https://fair-shift-nu.vercel.app

How to read this:

They test the rules and the input shapes I know about. No real worker's schedule is in them.
- Groups: main (13 clean cases), messy (5: LINE weekdays, `18-22`, overnight shifts, times in words, full-width digits, a texted English schedule), held-out (6, committed with their expected values before Fair Shift ever ran on them), real-style (5 inputs shaped like the ones an earlier version got wrong: a week in a header line, a monthly salary, `實領` on one line, gross and net pay, a New York payslip whose gross includes tips) and round-3 (11, one per input an internal review found handled wrongly or silently: a night shift into National Day, 9-hour shifts with no break written, a break at the end of the line, two shifts on one line, `18時-22時`, a line with no end time, `每小時196元`, `17.00 per hour`, only `實領` with a deduction-sized gap, payslip hours that do not match, seven days in a row). The real-style and round-3 cases were committed with their expected values before the code that handles them (commits "Add real-style eval cases with frozen expected values" and "Add round-3 eval cases with frozen expected values"). A round-3 case counts as right only if the amount is right and the result shows exactly the warnings it needs.
- One correction: the committed truth for the seven-days case missed that 2026-10-25 is Retrocession Day, a national holiday since 2025. The first demo-mode run showed it; the expected value was corrected and the input was not changed (noted in the case).
- 40 of 40 means the problems these cases describe are fixed, not that every real schedule will be read right. The same person wrote the cases and the fixes. Lines with a time that cannot be read are listed on the result and lower the confidence, so a miss on a real schedule should be visible rather than silent.

## Why an agent and not just a model

- Underpayment is common where students work. In the Ministry of Labor's 2025 inspection of businesses that often hire student and part-time workers, 465 of 1,852 broke labor law (25.11%), and the most common violation was not paying double for holiday work (134 cases). The ministry chose the businesses and put earlier violators first, so this is not a random sample (news release of 2026-07-31, https://www.mol.gov.tw/1607/1632/1633/96453/).
- Rates change after a model is trained. Taiwan's 2027 hourly minimum wage (NT$205) was decided on 2026-09-24 and announced by the Executive Yuan on 2026-10-01; the formal notice was not out when checked on 2026-10-14. Fair Shift finds that release with Tavily search during the run and shows the status instead of calling the rate "in force".
- The math is tiered and easy to get wrong (rest day 1 1/3 then 1 2/3, holiday double up to 8 hours, weekly 40 hours, New York tipped overtime on the full minimum wage). Code does it; the model never computes money.

## How it works

| Step | Who | What |
|---|---|---|
| 1. Redact | code | Names, ID numbers, phones, emails, account and card numbers, tax IDs, shop names and @handles are removed before any API call. |
| 2. Parse | Nemotron 3 Nano + code | The model turns the text into shifts and payslip numbers. A rule-based parser reads the same text independently; if they disagree, or a line with a time cannot be read, the result is marked "read with low confidence" and the unread lines are listed on the result. It handles `週五 18-22`, `18時-22時`, `下午5點半到10點`, two shifts on one line (`08-12 17-21`), breaks written at the end of a line (`中間休息半小時`), shifts across midnight, full-width digits, weekdays under a header such as `店長：10/5~10/11這週班表`, and hourly rates written as `時薪 196`, `每小時196元`, `$16/hr` or `17.00 per hour`. |
| 3. Stop and ask | code | No shift could be read, or no hourly rate (for example a monthly salary): the page names the box with the problem, shows no amount and runs no agent. The hourly rate box appears right in that message. |
| 4. Retrieve | code + Tavily | While Nano reads, the official seed pages are fetched with Tavily extract and one Tavily search looks for anything newer on official sites (for example the Executive Yuan's release on the 2027 minimum wage). Details: [docs/SOURCES.md](docs/SOURCES.md). |
| 5. Find rules | Nemotron 3 Super, two loops in parallel | One loop records dated amounts and Taiwan holidays, the other the multipliers and hour limits. Each rule goes in with an exact quote; code accepts it only if the quote is on a page retrieved in this run and code reads the same value back out of it. Rejected entries go back to the model with the reason. No new model turn after 40 seconds. |
| 6. Fill gaps | code | If a loop stops early, code reads the missing rules from the retrieved text through the same checks. Reports and the eval count agent records and fallback records separately. |
| 7. Compute | code | Pay per shift and segment, minimum wage top-up, premiums, tip credit, spread of hours, shortfall. Taiwan shifts across midnight are split at 0:00 (holidays are calendar days) but count as one workday for the 8-hour limit; two shifts on one day count together. When the input allows two readings, both are computed. |
| 8. Explain | Nemotron 3 Ultra + code | Ultra writes a short plain-language explanation in English and Chinese. It is rejected if it uses a number not in the calculation or simplified Chinese characters, and a code template is used instead. The message to the employer is always a code template that cites the articles. |

## What the result page shows

- A conditional headline: "Based on what you entered, you may be owed NT$1,176". If the payslip only shows take-home pay (實領), the headline says "up to", and a gap under 5% of the expected pay is shown as "may just be deductions" instead; the message to the employer then asks for the gross amount and the deductions and claims no amount.
- A bar that splits the expected pay into pay at your rate, any minimum wage top-up and each extra the rules add, against the payslip, with the gap marked.
- What the number depends on, with warnings first: no break written on a shift over 6 hours (the overtime is marked as depending on it), lines that could not be read, payslip hours that do not match the schedule, net pay instead of gross, the rest day and day off you chose, a minimum wage not yet formally announced.
- Two readings side by side when the input allows both: a holiday that may be your rest day; a shift with or without the usual break; a New York tipped worker's gross pay with or without tips.
- Also worth checking: 7 days in a row with no day off (LSA Art. 36), more than 12 hours in a workday, work on the regular day off.
- The reasons with article numbers, the rules used with their quotes and links (expanded), what to do next (1955, the local labor bureau, your attendance record, protection from retaliation, the time limit; New York: NYS DOL form LS223), a printable report and a message to the employer.
- "Was this right?" with Yes / No / Not sure and an optional comment (see Privacy).

Covered: Taiwan hourly minimum wage by date (including a decided 2027 rate), overtime beyond 8 hours a day or 40 a week, rest day work, national holidays (fixed and lunar for 2026 and 2027), the regular day off; New York State minimum wage by region, weekly overtime, tip credit and tipped overtime, spread of hours. Not checked: flexible schedules (變形工時), the monthly overtime cap, monthly-paid jobs, Art. 84-1 jobs, New York call-in pay and split-shift pay outside spread of hours, and more (listed on the result page).

## Privacy

- Before any model or search call the text goes through `lib/wage/redact.ts`. It can miss a name, so the page asks people to cover names too.
- What leaves the server: the redacted schedule and payslip go to Nebius Token Factory for parsing; the rule agent sees only dates and the rule list; Tavily receives only official URLs and fixed search words with a year; Ultra receives only computed numbers.
- What is stored: nothing you paste. No database, request bodies are not logged. The only log line the app writes is tester feedback (`app/api/feedback/route.ts`, prefix `[fair-shift-feedback]`): the answer (yes, no, not sure), an optional comment of up to 300 characters (run through the same redaction), the page language and the app version. Never the schedule, the payslip, the result or the IP. Rate-limit counters keep IPs in memory for a day per instance; official pages (never your text) are cached per URL per day; the host keeps its standard request logs (time, path, IP).

## Public demo caps

| Setting | Value |
|---|---|
| Checks per visitor | 6 per hour, 20 per day |
| Checks per day, all visitors | 60 per server instance |
| Model spend per day | US$1.5 per instance; US$0.05 per check |
| Tavily credits per day | 32 per instance |
| Tavily credits per month | live checks stop when the account has used 1,000 plan credits this month (all instances; checked with Tavily's usage API) |
| Agent time per check | 40 s, then code finishes from the retrieved text |

What that means in checks: a check that retrieves every page fresh used 2.6 Tavily credits for a Taiwan case and 4.6 for a New York tipped case (measured on 2026-10-14, as the app counts them: 1 per search, 0.2 per page extracted, 0.4 when a failed extract is retried in advanced mode). So the daily credit cap allows at least 6 fresh checks per instance, about 12 for Taiwan. Pages and searches are cached per URL per UTC day, so a repeat check that day costs 0 to 1 credit, and the 60-check cap is what limits those. Tavily's usage API updates with a delay (on 2026-10-14 it had not moved half an hour after four fresh test checks), so the monthly stop can overshoot by up to about a day of checks; the per-instance daily cap limits that. `/api/status` reports all of this (`caps`, `tavily.creditsPerColdCheck`, `tavily.coldChecksPerDay`, `tavily.monthlyStop`). When a cap is reached, page samples show the result saved from the latest eval run, labelled "Saved result"; your own input gets a "try again later" message.

## Run it

Node 20.9 or newer.

```bash
npm install
npm test             # 198 unit, pipeline and API tests, no network
npm run eval         # three-way eval (needs NEBIUS_API_KEY and TAVILY_API_KEY for the last two columns)
npm run readme       # rewrite the results block above from the newest live eval file
npm run timing       # one live run with its step timeline (TIMING_CASE=<case id>)
npm run dev          # http://localhost:3000
```

Keys come only from the environment (`NEBIUS_API_KEY`, `TAVILY_API_KEY`). Without them the app runs in a labelled demo mode: a scripted agent drives the same tools and checks over saved copies of the official pages. All settings are in `.env.example`; sources, the lunar holiday table and the retrieval notes are in [docs/SOURCES.md](docs/SOURCES.md).
